# Сопровождение RuDeFi

## Структура и запуск проверок

Из корня репозитория: `npm ci`, `npm run lint`, `npm test`, `npm run format:check`.
C++: `cmake -S . -B build && cmake --build build --parallel 2`.

CI проверяет JavaScript, HTML, формат служебных файлов, зависимости npm, shell-скрипты, C++ статическим анализатором, сборку бэкенда и контейнера. Контейнер проходит HTTP smoke-проверку.

## Доставка изменений

Workflow `Deploy` запускается только после успешного `Checks` для push в `main`. Pull request не получает SSH-ключ и не запускает доставку. Развёртывания сериализованы, SHA проверяется на сервере против текущего `origin/main`.

Environment `production` использует `DEPLOY_HOST`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS` и переменную `PUBLIC_URL`. Используется отдельный ключ с forced command `scripts/deploy-ci.sh`, без shell, PTY, forwarding или доступа к другим SSH-командам. Не помещайте обычный администраторский ключ в GitHub.

Сервер выполняет `scripts/update.sh`: fast-forward, сборка, перезапуск, проверка настоящего backend health endpoint, проверка и reload nginx. Корневой `update.sh` оставлен для совместимости со старыми командами.

Основной Compose: `infra/docker/docker-compose.yml`. Вариант за существующим reverse proxy: `infra/docker/docker-compose.standalone.yml`. Dockerfile: `infra/docker/Dockerfile`. Домен задаётся через `DOMAIN` и сохраняется в локальном `.rudefi-domain`. `scripts/render-nginx.sh` формирует игнорируемый git файл `infra/nginx/conf.d/default.conf` из шаблона. Сертификат должен соответствовать домену; повторные обновления не конфликтуют с локальной подстановкой домена.

## Защита от перегрузки

В основном nginx настроены:

- Лимиты запросов по реальному TCP-адресу клиента; произвольный `X-Forwarded-For` не считается доверенным.
- Общий лимит для API и отдельный лимит для тяжёлых операций.
- Не более двух одновременно выполняемых тяжёлых запросов на IP и шести суммарно.
- HTTP 429 при превышении лимитов, короткие таймауты, небольшой предел тела запроса.
- Разрешены только GET/HEAD для API; его текущее чтение не требует POST.
- Ограничения памяти, CPU, числа процессов и размера логов контейнера.
- Ограниченная очередь задач и таймауты бэкенда.

Проверка: `docker compose -f infra/docker/docker-compose.yml exec -T nginx nginx -t`.
Не запускайте нагрузочные тесты тяжёлых маршрутов на публичном сервере. Для безопасной проверки burst-лимита используйте несколько десятков запросов к `/api/config/status`, затем убедитесь, что обычный запрос проходит после восстановления лимита.

Это защита уровня приложения от спама и истощения ресурсов, а не гарантия против DDoS. Переполнение сетевого канала и массовый распределённый трафик требуют защиты провайдера или внешнего CDN/WAF. Если появится такой proxy, настройте доверенные диапазоны его IP и восстановление реального адреса; не доверяйте заголовкам от всего интернета.

Standalone-вариант не содержит собственного nginx: внешний reverse proxy обязан применять сопоставимые лимиты. Внешние API имеют отдельные квоты, которые nginx не увеличивает.

## Откат

Сначала сохраните ID работающего образа (`docker inspect rudefi-app --format '{{.Image}}'`) и пометьте его отдельным тегом. При ошибке поставьте предыдущий образ в тег `rudefi-app:latest`, выполните Compose `up -d --no-build app`, затем проверьте backend health и перезагрузите nginx. Не сбрасывайте локальные изменения конфигурации без резервной копии.
